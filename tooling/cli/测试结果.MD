## 问题清单

### BUG-001（open）
- 类型：CLI 行为 / 错误信息
- 标题：`asapflow.ps1` 包装脚本在部分 Windows 环境下因编码问题无法执行
- 发现时间：2026-04-29
- 复现步骤：
  1. 打开 Windows PowerShell 终端
  2. 执行 `.\bin\windows\asapflow\asapflow.ps1 auth whoami`
- 现象：
  - 脚本报 `字符串缺少终止符` 和 `语句块缺少右 '}'`
  - 错误信息中包含乱码，说明脚本文件以非 UTF-8 / GBK 编码读取时被破坏
- 影响：
  - 在部分 Windows 环境下 `.ps1` 包装脚本完全不可用，只能绕道调用 `asapflow.exe`
  - AI 工具和自动化脚本依赖 `.ps1` 的输出捕获行为，绕过后需要手动处理 `--output` 路径
- 建议：
  - 确认 `asapflow.ps1` 保存时统一使用 UTF-8 with BOM（PowerShell 5.1 的默认期望）
  - 或改为 UTF-8 no BOM 并在文件头加 `# -*- coding: utf-8 -*-` 注释

### BUG-002（open）
- 类型：API 返回 / 数据完整性
- 标题：`list-entities` / `list-features` 返回的 JSON 中文字段存在编码损坏，导致 JSON 解析失败
- 发现时间：2026-04-29
- 复现步骤：
  1. 执行 `asapflow system list-entities --output out.json`
  2. 用 `ConvertFrom-Json` 解析 `out.json`
- 现象：
  - `out.json` 中部分中文字段值出现乱码，例如 `"鍒涘缓浜?` 代替 `"创建人"`
  - 乱码出现在系统自动生成字段名等位置，导致 JSON 字符串未正确闭合
  - `ConvertFrom-Json` 抛出解析错误，无法得到 `.data` 数组
- 影响：
  - 任何依赖 CLI + PowerShell 解析返回的自动化脚本都会随机失败
  - 必须改用正则绕过 JSON 解析提取 id/code，增加脆弱性
- 建议：
  - 后端 API 统一以 UTF-8 输出，CLI 在写文件时确保不做二次编码转换

### BUG-003（open）
- 类型：功能完备性
- 标题：新增表单无"保存"按钮
- 发现时间：2026-04-29
- 复现步骤：
  1. 使用 `create-feature` 创建功能后，进入新建记录页面
- 现象：
  - 新建页面没有保存按钮，无法提交表单
- 原因分析：
  - `create-feature` 创建的 `detail` 场景 `actions` 为空数组
  - 需要在 `detail` 场景中显式添加 `save` 系统动作
- 影响：
  - 通过 CLI 创建的功能，默认不可用，必须额外执行补动作步骤
- 建议：
  - `create-feature` 初始化默认场景时，`detail` 场景应与 `list` 场景一样，自动带上系统动作（至少包含 `save`）
  - 或在文档中明确说明需要手动补充 `detail` 动作，并提供示例

### ISSUE-001（open）
- 类型：操作便利性
- 标题：无法通过 CLI 单次清空沙箱环境（无 `reset` 能力）
- 发现时间：2026-04-29
- 现象：
  - 清空所有菜单/功能/实体需要逐条调用 `delete-menu` / `delete-feature` / `delete-entity`
  - 全量清理耗时较长，且依赖正则绕过上述 JSON 解析 bug
- 建议：
  - 增加 `system reset-sandbox` 或 `system purge` 命令，支持在确认后一次性清空所有建模对象
